# Parity Audit — Identity

Date: 2026-06-03
Auditor: Claude

Scope: enterprise identity — SSO (SAML 2.0 + OIDC), SCIM v2 provisioning, MFA
(TOTP + WebAuthn/passkeys), MFA enforcement / step-up, session policy, password
policy, account linking, JIT provisioning, IdP metadata discovery + cert
rotation, LDAP/AD sync.

Method: code over README. The existing parity matrix
(`docs/parity-reference-matrix.md`, dated 2026-05-26) predates the SAML/OIDC RP,
MFA step-up, and WebAuthn work landed this cycle (migrations 025–027, ADRs
0015/0016) and is now stale for §3.14 SSO — it still says "Entra only; SAML/OIDC
stubs". The live route surface contradicts that; this audit supersedes it for
the identity rows.

## Critical Gaps (severity-ordered)

1. **LDAP/AD sync is a stub, not a feature (🟠, mislabeled "Partial" in matrix
   §3.14).** `app/api/admin/ldap/route.ts:85` returns `test_result:
   'simulated_success'` and `:166` enqueues a job with `type: 'compliance_export'`
   carrying an `ldap_sync` payload — no job handler dispatches on that payload,
   no LDAP client (ldapjs or equivalent) is a dependency, no bind/search/sync
   worker exists. Bind passwords are stored as the literal string `'sha256:***'`
   (`:119`). Any customer relying on AD sync will silently get nothing. Either
   build a real sync worker or remove the surface and mark Missing.

2. **No password policy (🔴).** BLUEPRINT §5.5 and Slack/Mattermost both expose
   complexity, history, expiry, and (Slack) breach checks. AAELink enforces only
   an 8-char minimum at `change-password/route.ts:27`. No admin policy object, no
   `system_config` key, no history table, no rotation. High enterprise-procurement
   risk.

3. **Legacy Entra route is an unhardened parallel auth path (🟠).**
   `app/api/auth/entra/route.ts` runs OAuth against Microsoft with NO PKCE, NO
   state/nonce (CSRF/replay exposed), NO MFA step-up, NO audit, a hardcoded
   30-day session, reads a separate `sso_configs` table the new OIDC path does not
   use, and JIT-creates users with an EMPTY `platform_role` (`:82`) — inconsistent
   with `ssoProvision.ts` which assigns `'employee'`. It duplicates and undercuts
   the secure OIDC RP flow. Retire it or route Entra through `ssoProvider`/`loginViaSso`.

4. **Session-policy fields are dead config (🟡).** `require_mfa_for_admin`,
   `max_sessions_per_user`, `single_session_mode`, `force_reauth_hours`, and
   `revoke_on_password_change` are typed in `sessionPolicy.ts` and settable via the
   admin route but never read at any enforcement site (verified by grep — zero read
   sites for `require_mfa_for_admin`). Notably BLUEPRINT §5.5 says "MFA mandatory
   for admins"; the flag to express it exists but does nothing.

5. **MFA gaps that weaken the factor (🟡).** Backup codes are generated and hashed
   but never consumed (no verify/burn path at login or step-up — `mfa/route.ts:156`
   only writes them). MFA enforcement for password logins gates *enrollment*, not a
   per-login second factor; a password user who enrolled once is never asked for a
   code again on subsequent logins (only SSO `enforce_mfa` providers get true
   step-up). SAML SP metadata publication and SLO are missing.

## Recommended Next Steps

1. Build a real LDAP sync worker (add ldapjs as a dep with an ADR, implement
   bind+search+attribute-map+deactivate-on-removal in `lib/worker.ts`, give it a
   distinct job type), OR delete the route and mark LDAP Missing. Stop returning
   `simulated_success`.
2. Add a password-policy module (`lib/auth/passwordPolicy.ts`) backed by
   `system_config`: complexity, min-length, history (new `password_history` table),
   optional rotation, optional HIBP k-anonymity breach check; enforce in
   `register`, `change-password`, and SCIM password set. Add admin route + tests.
3. Decide Entra's fate: route `/api/auth/entra` through the hardened OIDC RP
   (`startOidcAuthz`/`completeOidcAuthz` + `loginViaSso`) so it inherits PKCE,
   audit, MFA step-up, and consistent role assignment — or remove it.
4. Wire the dead session-policy fields: enforce `max_sessions_per_user` /
   `single_session_mode` at session create, `revoke_on_password_change` in
   change-password, and `require_mfa_for_admin` as an admin step-up gate (satisfies
   BLUEPRINT §5.5).
5. Add a backup-code consumption path (verify + single-use burn) to the MFA step-up
   and a password-login second-factor challenge; add SAML SP-metadata XML endpoint;
   scope + audit SCIM Group ops like Users.
6. Update `docs/parity-reference-matrix.md` §3.14: SSO is no longer "Entra only /
   stubs" — SAML + OIDC RP are real and tested. Reclassify LDAP from "Partial" to
   "Stub".

## Out of Scope

- AI/ML-driven identity (risk-based/adaptive auth, anomaly scoring) — per standing
  Slack-parity directive, AI/ML is out of scope.
- Native mobile biometric enrollment (no native client exists yet).
- mTLS + SPIFFE/SPIRE service identities and OpenFGA ReBAC (BLUEPRINT §4.3/§5.5
  platform-architecture drift, tracked separately in the reference matrix; not an
  end-user identity behavior).
- Go `identity-svc` extraction (BLUEPRINT §4.3 target architecture; current
  implementation is Next.js route handlers and that is the audited surface).
