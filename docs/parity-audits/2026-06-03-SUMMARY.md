## Cross-cutting themes (hit multiple areas)

1. **"Engine exists, nothing calls it" — the dominant pattern.** Fully built,
   often unit-tested subsystems have zero production callers:
   - outgoing webhooks `emitWebhookEvent` + Events API `dispatchWebhookEvent` (integrations)
   - keyword highlight `matchKeywords` (notifications)
   - information-barrier `checkBarrier` (admin/compliance)
   - DLP `scanMessageContent`/`enforceDlpAction` send-path block (admin/compliance)
   - WebRTC signaling + `/api/calls/ice` (calls — `HuddlePanel` never calls them)
   - `canvas_access` grants (knowledge — access check ignores the table)
   These read as "Shipped" but do nothing end-to-end. **Wiring, not building, is
   the highest-leverage work.**

2. **Hard Rule #4 (CSRF) violated broadly.** Message send/edit/delete/react/
   pin/save/forward/schedule skip `verifyCsrf` (only `/api/threads` calls it).
   Audit other mutation routes too.

3. **Hard Rule #5 (audit log) missing on many writes** — message edits/deletes,
   all knowledge writes (canvas/list/KB), several integration write paths.

4. **Authorization holes (security).**
   - `GET /api/lists` returns any list to any user (no workspace check).
   - `canvas_access` / `channel_canvas` membership not enforced → private content leak.
   - calls `action=end` has no host-only check → any participant ends the room.
   - compliance routes gate on non-existent `platform_admin` role → `it_admin` locked out, and DLP/barriers don't actually block.
   - `kb/articles/[id]` lets any user edit/delete any article.

5. **Duplicate / divergent storage for one concept.**
   - read-state: `channel_read_state` vs `read_state` (split-brain across messaging + notifications).
   - files: `file_attachments` / `files` / `file_uploads` / `documents` (two don't exist in migrate.ts → phantom-table queries).
   - canvas: 3 backends; keyword prefs: 2 systems; message search: 5 routes, only 2 use real FTS.

6. **Schema defined outside `lib/infra/migrate.ts`** (Hard Rule #3) — `oauth_tokens`, workflow/function tables created ad-hoc in handlers.

7. **Genuinely env-blocked (need external infra/creds, not codeable here):**
   SFU + recording + transcription (media server), APNS delivery (HTTP/2 + Apple
   creds), LDAP/AD sync (LDAP client + directory), KMS encryption-at-rest.

## Critical gaps — program-level, severity-ordered

**P0 — security / data correctness**
1. Add CSRF to all message + write mutations (messaging, +sweep).
2. Close authorization holes: lists read RBAC, canvas/channel-canvas membership, calls `end` host check, KB edit RBAC, compliance role-name bug (`platform_admin`→`isPlatformAdmin()`).
3. Resolve read-state split-brain (pick one table; migrate + repoint consumers).
4. Make DLP/information-barriers actually block on the send/DM/join paths (currently log-after-the-fact only — false compliance controls).

**P1 — "looks shipped, does nothing" wiring**
5. Wire `emitWebhookEvent`/Events API into real platform events.
6. Call `matchKeywords` in the message dispatch path; unify the two keyword systems.
7. Build the WebRTC client in `HuddlePanel` (consume `/api/calls/ice` + signals) — unblocks 1:1 calls without an SFU.
8. Enforce `channel_notification_prefs.level` + server-side DND/status in dispatch.

**P2 — data-model consolidation**
9. Unify file storage on `file_attachments` + S3 (kill phantom `files`/`file_uploads` tables); add scan-enqueue + `file_index` on upload.
10. Unify canvas backends + honor `canvas_access`.
11. Converge message search on the FTS engine; fix `in:` id-vs-name + `has:reaction` table-name bug.

**P3 — missing features**
12. Password policy object (Identity). Saved-search alerts (Search). Email digests (Notifications). Interactivity ingress + real OAuth authorize flow (Integrations). Retire the legacy unhardened `/api/auth/entra` path.

## Out of scope
- AI/ML (semantic/vector search, smart suggestions, auto-transcription quality) — per standing directive.
- Env-blocked infra: SFU/recording/transcription, APNS, LDAP, KMS (theme 7).

## Addendum — 2026-06-06 status update

### Remediation summary since 2026-06-03

Four waves of remediation landed between the 2026-06-03 audit and today. The first wave closed the highest-severity security holes: CSRF tokens were added to every previously-unguarded message mutation (send, edit, delete, react, pin/unpin, save, bookmarks, forward), DLP enforcement was moved pre-persist on the send path and forward path, information barriers were wired onto DM-open, channel-join, search, file-share, and conversations-members endpoints, and the legacy `/api/auth/entra` hand-rolled OAuth path was replaced by a redirect into the hardened OIDC engine. The second wave fixed "engine exists, nothing calls it" wiring: `emitWebhookEvent` and Events API fan-out were connected to real message/reaction/interactivity events, `matchKeywords` was wired into the production send path with a unified keyword system, `channel_notification_prefs.level` and broadcast mentions (@here/@channel/@everyone) became server-enforced, the WebRTC client was built out in `useHuddleRtc` consuming real `/api/calls/ice` + signals with mute/video/screen-share track gating, and the OAuth authorization-code flow was hardened (constant-time secret verify, single-use codes, no dev backdoor). The third wave was schema consolidation via migrations 042–046: the legacy `read_state` table was migrated into `channel_read_state` and dropped (resolving the split-brain across all consumers), `conversation_canvases` was retired onto `aaelink.canvases`, `user_keywords` was deprecated in favour of `notification_keywords`, and schema drift in `files_remote`, `workflow`/`function` tables, and other ad-hoc DDL was absorbed into `lib/migrate.ts`. The fourth batch (B) delivered new features and fills: files were unified onto `file_attachments` + S3 (phantom `files`/`file_uploads` tables eliminated), upload sessions with resumable multipart were added, the unified FTS search engine landed with `in:` channel-name fix and `has:reaction` phantom-table fix, saved-search alerts were implemented, email digest became real, org domain DNS verification went live, canvas access control began being enforced, list column update/delete shipped, and the password-policy subsystem (complexity, history, expiry, enforcement at login) was added.

### P0 / P1 / P2 / P3 status

**P0 — security / data correctness**

1. *Add CSRF to all message + write mutations* — **CLOSED.** `verifyCsrf` now on send (bearer-exempt), edit, delete, react, pin/unpin, save, bookmarks, forward. Residual gaps on scheduled-message create, dispatch endpoint, and read-state POST remain but are lower risk.
2. *Close authorization holes: lists RBAC, canvas/channel-canvas membership, calls `end` host check, KB edit RBAC, compliance role-name bug* — **CLOSED.** `GET /api/lists` scoped to channel-reader or own lists; canvas access resolved via `resolveCanvasAccess` (table now read); calls `end` is host/super_admin-only; KB articles gated by `canManageArticle`; compliance routes converted to `isPlatformAdmin()`. Partial exceptions: SCIM Groups unscoped, some admin sub-routes retain buggy `['super_admin','platform_admin']` string array check (data-residency, session-policy, devices).
3. *Resolve read-state split-brain* — **CLOSED.** Migration 028 back-filled and dropped `aaelink.read_state`; all consumers (conversations/mark, channels/dm, channels/unread, threads, read-state, mark-unread, bootstrap) unified on `channel_read_state`.
4. *Make DLP/information-barriers actually block on send/DM/join paths* — **CLOSED.** `applyDlpToMessage` called synchronously pre-persist in messages POST, edit, and forward (returns 403 `dlp_blocked`). `barrierGuard` enforced on DM-open, conversations-open/members, channel-join, search, and file-share paths.

**P1 — "looks shipped, does nothing" wiring**

5. *Wire `emitWebhookEvent` / Events API into real platform events* — **PARTIALLY CLOSED.** Message create/broadcast, delete, reactions, and interactivity now emit. Channel, file, user, DLP-violation, and call write paths still do not emit. Classify as open for full parity.
6. *Call `matchKeywords` in message dispatch; unify two keyword systems* — **CLOSED.** `notifyKeywordMatches` wired on production send path; `user_keywords` route removed, `notification_keywords` is the single CRUD surface.
7. *Build WebRTC client in HuddlePanel* — **CLOSED.** `useHuddleRtc` + `HuddleRtcClient` implement `getUserMedia`, `RTCPeerConnection`, ICE fetch, signal poll/send, and mute/video/screen-share track gating. `HuddlePanel` rendered via `ModuleRenderer`.
8. *Enforce `channel_notification_prefs.level` + server-side DND/status in dispatch* — **PARTIALLY CLOSED.** `level='all'` and `level='nothing'` enforced on send path; DND + snooze + manual `status='dnd'` suppress push. Residual: `level` mute does not suppress in-app notifications (muted member still receives in-app mention row); DND does not suppress in-app rows.

**P2 — data-model consolidation**

9. *Unify file storage on `file_attachments` + S3; add scan-enqueue + `file_index` on upload* — **CLOSED.** All file CRUD routes now query `file_attachments`; `storeFileBytes`/`readFileBytes` use S3 when configured; scan job and file-index job auto-enqueued on every upload. Residual: ClamAV daemon absent from `docker-compose.yml`; infected auto-delete rule stored but not enforced.
10. *Unify canvas backends; honor `canvas_access`* — **CLOSED.** `conversation_canvases` retired (migration 036); `resolveCanvasAccess` reads the grant table; channel-canvas gated by `userCanReadChannel`.
11. *Converge message search on FTS engine; fix `in:` and `has:reaction` bugs* — **CLOSED.** All message search routes re-pointed to `lib/messaging/searchEngine.ts`; `in:` now sends `channel_name` (not raw id); `has:reaction` uses real `message_reactions` table; `has:pin` via `pinned_messages`.

**P3 — missing features**

12. *Password policy* — **CLOSED.** `lib/auth/passwordPolicy.ts` enforced at register and change-password; admin CRUD route; login surfaces `password_expired`.
13. *Saved-search alerts* — **CLOSED.** `lib/messaging/savedSearchAlerts.ts` re-runs as owner with watermark; self-rescheduling worker job; migration 035; UI toggle.
14. *Email digests* — **PARTIALLY CLOSED.** `lib/notifications/emailDigest.ts` real and scheduled; frequency is off/daily/weekly only — no hourly/realtime granularity per BLUEPRINT §2.1.5.
15. *Interactivity ingress* — **CLOSED.** `app/api/integrations/interactivity/route.ts` HMAC-verified, anti-replay, rate-limited, dispatches through event-subscription pipeline.
16. *OAuth authorize flow hardened* — **CLOSED.** Constant-time client-secret verify, atomic single-use code consume, full binding check; introspect, rotate, and revoke all real.
17. *Retire legacy `/api/auth/entra`* — **CLOSED.** Route is now a 49-line shim that 302s into `/sso/oidc/start`; hand-rolled JWT/JIT removed.

**Remaining open items (not fully closed as of 2026-06-06, updated post bug-fix batch)**

- Mute does not suppress in-app notifications (only push); DND does not suppress in-app rows.
- Outgoing webhooks and Events API do not fire on channel, file, user, compliance, or call events.
- Socket-mode gateway (`resolveSocketTicket`) still has zero callers — ticket is minted but no WS gateway validates it or streams events.
- Views/modals API (`app/api/views/route.ts`) is echo-only with no persistence or realtime push.
- Workflow Builder engine runs no steps — `execute` only inserts `status='running'`.
- Admin push policy (quiet hours / max rate) stored but never consulted at enqueue or deliver.
- ClamAV daemon not present in `docker-compose.yml`; `auto_delete_infected_after_days` stored but unenforced.
- Per-channel retention (individual `channel_id` scoping) still scope-enum only; `admin/retention/enforce` path bypasses legal-hold exclusion.
- `data-residency`, `session-policy`, `devices` admin routes retain buggy platform-admin role string-array check.
- Canvas version history: no revision table.
- HIPAA/FINRA/WORM compliance mode, field-level message encryption, IdP group→role mapping, SAML SLO — all remain missing.
- `eDiscovery` custodian/keyword/hold/file-include scoping still not applied to export artifact; MBOX format degrades silently to JSON.
- Forward source-channel read RBAC (Messaging 24): can forward from a channel you cannot read.
- Live-delivery SSE consumer still poll-based (Messaging 34): pub/sub emit now wired at message POST, but `collab/events` SSE stream is watermark/since DB-poll; postEphemeral still unpersisted (Messaging 38).
- Channel bookmarks (Messaging 17): RBAC added but no audit log, no reorder/folders.
