# v0.0.34-alpha — Redis pub/sub auto-connect (multi-node fan-out groundwork)

**Released:** 2026-05-18

Closes the highest-leverage finding from `docs/audit-2026-05-18.md` §1.1: the production Redis adapter exists in `lib/redisPubSub.ts` but `getPubSub()` never called `.connect()` on it, so every `publish()` threw `redis_not_connected`. Even with `REDIS_URL` set, multi-node fan-out was a 503 wall, not the documented graceful fallback.

This release wires it up. The work is foundation only — no user-visible behavior change in single-node mode. Multi-node deployments now have a working path to enable Redis fan-out by setting two env vars and adding one optional dependency.

## What changed

### New: `lib/redisClientFactory.ts`

Two exports:

- `wrapIoredis(client)` — adapter that maps an `ioredis`-shaped client into the simpler `RedisLikeClient` shape that `RedisPubSub` consumes. Handles the asymmetry between `ioredis`'s `(channel, message)` `'message'` events and its `(pattern, channel, message)` `'pmessage'` events.
- `defaultRedisClientFactory(url)` — async factory that **lazily** dynamic-imports `ioredis` and returns a `RedisLikeClient`. Throws `redis_client_unavailable` when the package is not installed; the caller catches and falls back to `MemoryPubSub`.

Lazy import means `ioredis` stays an optional dependency. Unit tests, dev runs without `REDIS_URL`, and `npm install --omit=optional` deployments all keep working.

### Updated: `lib/redisPubSub.ts`

`getPubSub()` now seeds a `MemoryPubSub` synchronously and kicks off a background Redis connect when `REDIS_URL` is set. Once the connect resolves successfully, the global adapter is swapped in place; subsequent `getPubSub()` calls return the connected `RedisPubSub`. On failure, the runtime stays on `MemoryPubSub` and logs a one-time warning. The new `getPubSubAsync()` export waits for the in-flight connect, for callers that need the connected adapter immediately.

`RedisPubSub.connect()` was widened to accept `(url) => RedisLikeClient | Promise<RedisLikeClient>` so it can call the new async factory.

### `.env.example`

Two new documented variables:

```bash
# REDIS_URL=redis://127.0.0.1:6379
# WS_GATEWAY_URL=wss://ws.aaelink.example.com
```

`REDIS_URL` is documented as **required** for any deployment running more than one Next.js node behind a load balancer, with the prior single-node-only failure mode called out explicitly.

`WS_GATEWAY_URL` is documented now to set the contract for the v0.0.35 WS gateway service (this release does not implement the gateway yet — `app/api/ws/route.ts` still returns 426).

## TDD discipline

`tests/redisClientFactory.test.ts` (10 new tests) pins:

- `wrapIoredis` returns a `RedisLikeClient` with the right shape
- `publish` / `subscribe` / `unsubscribe` / `psubscribe` / `punsubscribe` all forward correctly to the underlying `ioredis` client
- `'message'` events route to the `onMessage` handler with `(channel, message)` signature
- `'pmessage'` events route to the same handler with the *channel* (not the pattern) plus message — matching what `RedisPubSub` expects
- `quit()` propagates to the underlying `ioredis` client
- The `getPubSub()` fallback path stays on memory when `REDIS_URL` is unset, returns the same instance across calls, and rebuilds cleanly after `resetPubSub()`

The test file's `FakeIoredis` does **not** auto-fire events on publish — it exposes `emitMessage` / `emitPmessage` test helpers so tests reflect the real `ioredis` semantics (publishers don't see their own messages unless subscribed; that round-trip happens through the broker).

## Out of scope (deferred)

- **Adding `ioredis` to `package.json`.** Production deployers add it to their root `dependencies`; we don't bundle it here so that single-node and unit-test deployments stay clean.
- **`MULTI` / `EXEC` transactions and Streams.** This release only uses `PUBLISH` / `SUBSCRIBE`. Streams are tracked for v0.0.36 specifically.
- **Sentinel / Cluster URLs.** `REDIS_URL` is a single-node URL. Multi-node Redis topologies are tracked for a later release (the `IoredisLikeClient` interface already accepts whatever ioredis returns; it should "just work" but is unverified).
