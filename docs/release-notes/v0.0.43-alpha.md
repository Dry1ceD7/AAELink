# v0.0.43-alpha — foundation: real ESLint, coverage measurement, central logger, duplicate-index drop

**Released:** 2026-05-19

Closes the highest-priority audit findings from `docs/audit-2026-05-19.md` (Phase 1). Foundation release — no user-visible UI changes; downstream releases (v0.0.44+) build on this.

## What changed

### A — Real ESLint rules (audit B6)

`eslint.config.mjs` is no longer the v0.0.42 placebo (`{ ignores: ['.next/**'] }`). Now ships:

- `typescript-eslint/recommended`
- `eslint-plugin-react-hooks` rules (`rules-of-hooks` as **error**, `exhaustive-deps` as warning)
- Sensible ignores (`.next/`, `desktop/`, `.claude/`, `.kiro/`, `.agents/`, `.graphify/`)

Caught **one real production bug** while landing this:

- `app/components/SlaCountdown.tsx:49` — `useMemo` was called after an early return, violating `react-hooks/rules-of-hooks`. Silent React unmount whenever `slaDueAt` toggled null↔value. **Fixed.**

Also cleaned up: 4 inline `require('crypto')` callsites → top-level imports; 3 dangling `eslint-disable @next/next/no-img-element` comments referencing a now-unloaded plugin.

130+ unused-variable / `any` / `prefer-const` warnings remain demoted to `warn`. v0.0.44+ codemods will promote them back to `error` once the cleanup lands.

**Note on ecosystem state:** `eslint-config-next/core-web-vitals` is incompatible with ESLint 10 today (its bundled `eslint-plugin-react@7.x` calls the removed `context.getFilename()` API). Reinstate when that ships.

### C — Central logger (`lib/log.ts`)

Process-scoped logger separate from the existing request-scoped `lib/logger.ts`. Two complementary loggers:

| Logger | When |
|--------|------|
| `lib/log.ts` (this release) | Module-level — worker tasks, WS gateway, schema migrations, lib-level errors |
| `lib/logger.ts` (existing) | Request-scoped via `createRequestLogger(req, route, userId?)` — attaches trace id + records HTTP metrics |

Both share `LOG_LEVEL` (`debug`/`info`/`warn`/`error`/`silent`). Both emit to stdout, so they interleave under any log shipper. JSON-line output in production, pretty-printed dev output otherwise.

6 tests pin level routing, name-tag rendering, and JSON field appending. First migration sample: `lib/redisPubSub.ts` connect-failure warning.

### D — Drop 16 redundant indexes (audit B2)

Postgres MCP (`analyze_db_health`) caught 16 indexes that are fully covered by primary keys or unique compound indexes. Each was costing one extra B-tree update on every INSERT/UPDATE to its table.

Idempotent `DROP INDEX IF EXISTS` block added to the end of `lib/migrate.ts`. Existing deployments drop on next `ensureSchema()`. Fresh deployments: redundant indexes never get created (still in `CREATE INDEX IF NOT EXISTS` form upstream — to be removed in v0.0.44 cleanup).
