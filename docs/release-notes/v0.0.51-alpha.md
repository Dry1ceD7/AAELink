# v0.0.51-alpha — Composer polish (send-button states + reduced-motion guard)

**Released:** 2026-05-19

Pivots the Wave-2 sweep from admin panels to the highest-traffic user surface — the message composer. CSS-only change adds three small but visible polish wins to the send button and ensures the pending-message pulse animation respects `prefers-reduced-motion`.

## What changed

`app/styles.css` — the `.send-button` block (used in `app/components/chat/Composer.tsx` for both edit-mode and send-mode buttons, plus the same class on thread-panel composers) now has:

### 1. `:active` press feedback

Pressing the button now scales it down to `0.96` and dims via `filter: brightness(0.94)`. Slack-style "I felt that click" feedback. Bound to `:not(:disabled)` so a busy/disabled state never animates.

### 2. `:disabled` and `[aria-disabled="true"]` styling

Disabled send buttons now show a clear visual disabled state — `opacity: 0.55`, `filter: grayscale(0.25)`, and `cursor: not-allowed`. Previously the button only changed via the `disabled` attribute's default browser styling, which was inconsistent across themes (especially the dark theme, where the default looked nearly identical to the enabled state).

### 3. `transform` + `opacity` added to the transition list

The existing `transition` list (`background 0.15s ease, filter 0.15s ease`) is extended to also tween `transform` (using the `--motion-instant` token, 80 ms) and `opacity` (using `--motion-fast`, 0.15s). This means the press scale and disabled-fade now animate smoothly instead of snapping.

### 4. Reduced-motion guard for the pending-message pulse

The `.message--pending` selector previously animated `pendingPulse 1.5s ease-in-out infinite` regardless of user preference. Added a `@media (prefers-reduced-motion: reduce)` block that:

- Disables the pulse animation entirely (constant `opacity: 0.65` instead of pulsing 0.6 → 0.85)
- Disables the send-button press scale (no `transform` change on `:active`)

This is the same accessibility pattern already shipped on the `<Skeleton>` primitive in v0.0.44.

## Token reuse

The transition durations now use the design tokens shipped in v0.0.44:

- `--motion-instant` (80 ms) for the press scale
- `--motion-fast` (0.15s) for background, filter, opacity

If a future release changes those token values, the send button moves with the rest of the design system instead of staying on the old hardcoded `0.15s ease` literal.

## What's intentionally NOT yet done

The composer polish item in the audit (F2/F3) also names:

- **Mention pill CSS class enhancement** — `.mm-mention` already exists and renders correctly. No change needed this release.
- **Expand-mode (Cmd+Shift+F)** — turns the composer into a full-height editor. This needs both a state hook and a layout shift; deferred to v0.0.52 or later.
