# v0.0.28-alpha — Drag-to-reorder default sidebar sections

**Released:** 2026-05-15

Closes audit §1.4 follow-on. Slack lets users drag the default sidebar
sections (Starred, Channels, DMs) into any order they like; AAELink now
matches that.

## What changed

### Frontend

- **`lib/sidebarOrder.ts`** (new) — pure ordering module. The four slot ids:

  | Slot | Renders |
  |------|---------|
  | `starred` | Starred section (only when at least one channel is starred) |
  | `__custom__` | All custom user-defined sections from v0.0.22 |
  | `channels` | Public/private channels the user belongs to |
  | `dms` | Direct messages and group DMs |

  `Enterprise` and `Administration` stay pinned at the bottom — they're
  navigation, not conversation.

  Public API:
  - `DEFAULT_SIDEBAR_ORDER` — Slack-default render order (Starred → Custom → Channels → DMs)
  - `KNOWN_SLOTS` — all slot ids in canonical order
  - `isValidSidebarOrder(value)` — type-safe predicate
  - `normaliseSidebarOrder(value)` — coerce arbitrary input into a valid order; preserves user-saved partial state and appends new slots at the end on version upgrades
  - `moveSlot(order, from, to)` — pure index swap; clamps out-of-range indices
  - `readSidebarOrder()` / `persistSidebarOrder(order)` — localStorage round-trip

- **`app/home/ChannelSidebar.tsx`** — now renders sections by walking the
  user-saved order. Each `SidebarSection` accepts `draggable` + the four
  HTML5 DnD events. The `dragHandlersFor(slot)` helper wires them up
  consistently. Drop persists via `persistSidebarOrder`. Drag-over
  highlights the target section with a 2px dashed accent outline so the
  drop target is unambiguous.

- **`app/styles.css`** — `.channel-section--drag-over` styles. Cursor is
  `grab` on draggable section heads, `grabbing` while pressed.
  `prefers-reduced-motion` swaps the dashed outline for solid (no
  animation difference, just visual clarity).

### Tests

`tests/sidebarOrder.test.ts` — 20 unit tests covering:

| Group | Cases |
|-------|-------|
| Defaults | (1) order matches the v0.0.27 hardcoded layout; (2) every known slot appears exactly once |
| Validation | (3) accepts default; (4) accepts permutations; (5) rejects unknown slot ids; (6) rejects duplicates; (7) rejects missing slots; (8) rejects non-array input |
| Normalisation | (9) garbage → default; (10) valid → identity; (11) older saved order with new slot → user order preserved + new slot appended; (12) unknown slots dropped, missing ones appended |
| `moveSlot` | (13) moves a slot to a target index; (14) no-op move (same index); (15) clamps out-of-range indices; (16) does not mutate input |
| Persistence | (17) returns default when nothing stored; (18) malformed JSON → default; (19) invalid stored value → default; (20) `persistSidebarOrder` is a no-op for invalid input |

Total: **1,357** tests (+20). Zero regressions.

## How it feels

- Hover any section header → `cursor: grab`. Press → `cursor: grabbing`.
- Drag a section onto another section header → that target gets a 2px
  dashed accent outline.
- Drop → the dragged section moves to the target's position. Saved
  immediately; restores after reload.
- DnD only fires from sections with `draggable=true`. Enterprise / Administration / "More" submenu / channel rows themselves are NOT
  draggable — only the four conversation slots.
