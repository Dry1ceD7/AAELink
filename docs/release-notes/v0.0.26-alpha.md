# v0.0.26-alpha — Animation sweep round 2, legacy v1 retired, Superpowers methodology

**Released:** 2026-05-15

## What changed

### Frontend — animation token sweep round 2

Six high-traffic admin/utility panels migrated from inline `transition:` strings + hand-rolled `onMouseEnter` / `onMouseLeave` handlers to the `aae-hoverable` and `aae-chevron-toggle` utility classes from v0.0.23/24. Hover feel is now consistent with the rest of the app and honours `prefers-reduced-motion` automatically:

- `app/components/admin/EKMPanel.tsx`
- `app/components/admin/EMMPanel.tsx`
- `app/components/admin/DomainClaimingPanel.tsx`
- `app/components/admin/LegalHoldPanel.tsx`
- `app/components/admin/AuditLogPanel.tsx`
- `app/components/CustomEmojiPanel.tsx`

Inline-`transition:` count is down to **19** components (was 24 at v0.0.25, 30+ at v0.0.22). The remaining ones are mostly modals and lightboxes that have specific animation requirements; round 3 will mop up the rest.

### Documents pipeline — legacy v1 fallback retired

`lib/puzzleBox/assemble.ts` no longer renders pre-v2 templates. The old `html_source` + `{{placeholder}}` branch is replaced with a clear error:

```
{ ok: false, code: 'legacy_template_unsupported',
  message: 'Template "<name>" was authored against the v1 placeholder
            engine. Re-create it in the Puzzle Box editor to upgrade
            to schema_version="2".', recoverable: false }
```

`html_source` and `css_source` columns still load (back-compat — no migration required) but are not rendered. The Puzzle Box editor only writes `schema_version='2'` rows since v0.0.20, so any row hitting the new error branch was authored before that migration. `lib/templateEngine.ts` is now only imported by `app/api/documents/find-replace/route.ts`; once that's migrated to the block-tree path it can be deleted.

### Methodology — Superpowers installed

Adopted [obra/superpowers](https://github.com/obra/superpowers) v5.1.0 (MIT) as the project methodology:

- **Vendored at** `.claude/skills/superpowers/` — the 14 canonical SKILL.md files plus a `README.md` documenting the install and re-vendoring process.
- **Always-on summary** at `.kiro/steering/superpowers.md` — `inclusion: always` so the methodology lands in every chat session.
- **Activatable per-skill cuts** at `.kiro/skills/superpowers-{tdd,debugging,verification}.md` — adapted to AAELink's conventions (Vitest not Jest, `tests/` not `__tests__/`, the four-gate verification doctrine).
- **Auto-fire hook** `superpowers-four-gates` — `postToolUse` on write tool types prompts the agent to assess each batch as a checkpoint and run all four gates if so. Closest single-turn equivalent to the upstream `fswatch`/agent-bridge loop.

### Audit document

`docs/audit-2026-05-15.md` — fresh full-project QA pass against the four gates plus a security/discipline scan. Surfaces two **P0 findings** that drive the v0.0.27 plan:

- **CSRF coverage is patchy** — only 12 of 236 routes import `verifyCsrf`. SameSite=lax cookies are the primary defense and remain solid, but token belt-and-suspenders are missing.
- **Audit-log coverage is patchy** — only 11 of 236 routes call `writeAuditLog`. Compliance/forensic-trail gap, not a security hole.

Both have an identical fix shape: lift the check into `tracedRoute` so wrapping a method automatically does the right thing. That's the v0.0.27 cut.
