# v0.0.31-alpha — compact mode actually shrinks the chrome

**Released:** 2026-05-18

Closes the "sidebar density modes that actually differ" item from `docs/audit-2026-05-15.md` §mid-tier. Before this release, the **Message density** select in Preferences (Cozy / Compact) only hid avatars in the message timeline. The repo already shipped a separate `lib/uiDensity.ts` module wired to a `data-mm-density` attribute, with comprehensive CSS rules that tightened the sidebar header, channel search, channel rows, channel header, composer wrap, editor textarea, and editor toolbar — but no UI surface ever flipped that attribute, so those rules never fired in production. This release wires the existing setting through.

## What changed

`messageDensity` (`'cozy' | 'compact'`) is now the single source of truth for compact UI mode.

- `lib/userPreferences.ts` — `applyPreferenceSideEffects` now also calls `persistUiDensity('compact' | 'comfortable')` so flipping the Preferences select tightens the sidebar, channel header, and composer in the same beat as the message timeline. The `data-mm-density` localStorage key (`aaelink_ui_density`) stays in sync with the `messageDensity` field on the prefs blob.
- `app/layout.tsx` — the inline boot script that runs before React hydrates now mirrors `messageDensity` to `data-mm-density` and seeds the `aaelink_ui_density` key from the same source. This eliminates first-paint flicker on cold loads when the user has compact mode saved.
- `app/components/PreferencesModal.tsx` — the **Message density** select description was misleading ("Compact is text-only"). Rewritten as: *"Cozy shows avatars and generous spacing. Compact tightens the sidebar, channel header, composer, and message timeline."*

No new state, no new API surface, no migration. Existing users with `messageDensity = 'compact'` saved get the broader compact mode automatically on next page load.
