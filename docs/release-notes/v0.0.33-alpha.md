# v0.0.33-alpha — workspace-scoped slash commands in autocomplete

**Released:** 2026-05-18

The `GET /api/slash-commands?workspace_id=...` endpoint shipped at v0.0.7-alpha. The Composer never read from it. Workspace-installed custom slash commands existed in the database, were listed by the admin UI, were execute-able via `POST`, but never showed up in the autocomplete dropdown — users had to know the command name and type it from memory. This release wires the fetch through.

## What changed

New `lib/useWorkspaceSlashCommands.ts` module:

- `selectCustomCommands(payload)` — pure mapper that drops built-ins from the API response and reshapes the rest into the `{ name, description, usage }` triple the Composer consumes. Safe against malformed payloads.
- `useWorkspaceSlashCommands(workspaceId)` — React hook that fetches once per workspace and caches the promise in a module-level `Map<string, Promise<...>>` so repeat mounts share the result.
- `_resetWorkspaceSlashCommandsCache()` — exposed for tests; never called in production.

`app/components/chat/Composer.tsx` now consumes the hook and merges its result into the existing autocomplete `useMemo`. Custom commands appear at their alphabetical position in the dropdown alongside the built-ins. Names that collide with a built-in are dropped (the API rejects `conflicts_with_builtin` at registration time, so this is defensive only).

## TDD discipline

`tests/useWorkspaceSlashCommands.test.ts` (9 new tests) pins the mapper:

- Null and missing-field tolerance
- Built-ins are dropped (`is_builtin: true` filter)
- Custom commands without `is_builtin` set are kept (defensive default)
- Empty-name entries are dropped
- Synthesizes `description` and `usage` strings when the API omits them

The hook itself is a thin React wrapper; testing it would require a happy-dom environment fixture and a fetch mock. The mapper is the only piece with non-trivial behavior, so tests focus there. The hook's contract — single fetch, cached, returns `[]` on error — is small enough to read from the source.
