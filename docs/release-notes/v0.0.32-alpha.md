# v0.0.32-alpha — slash command registry de-duplication

**Released:** 2026-05-18

The Composer's slash-command autocomplete listed 21 commands from a hardcoded array. The lib registry in `lib/slashCommands.ts` exported its own list of 20 different but overlapping commands. The two had drifted: the Composer dropped `/topic` from its display, the lib was missing `/code`, `/clear`, and `/shortcuts`. This release makes the lib registry the canonical source of truth and forces the Composer to read from it.

## What changed

`lib/composerSlash.ts` adds a small `getClientSlashCommands()` export that lists the seven commands the Composer handles entirely client-side (`/me`, `/shrug`, `/tableflip`, `/unflip`, `/code`, `/clear`, `/shortcuts`). The Composer now derives its autocomplete list as `getClientSlashCommands()` ⊎ `getSlashCommands()`, with client entries winning on overlapping names so descriptions match the actual client behavior.

The hardcoded 21-entry `SLASH_COMMANDS` array in `app/components/chat/Composer.tsx` is gone. The array is now built once via `useMemo`:

```typescript
const SLASH_COMMANDS = useMemo(() => {
  const client = getClientSlashCommands()
  const clientNames = new Set(client.map(c => c.name))
  const lib = getSlashCommands().filter(c => !clientNames.has(c.name))
  return [...client, ...lib]
    .map(c => ({ name: c.name, desc: c.description }))
    .sort((a, b) => a.name.localeCompare(b.name))
}, [])
```

User-visible result: typing `/` in the composer now shows every command the system actually supports, sorted alphabetically, descriptions accurate.

## TDD discipline

`tests/composerSlash.test.ts` (6 new tests) pins the new `getClientSlashCommands()` export so future drift gets caught. The "every client command name is actually intercepted by `expandComposerSlash`" test specifically guards against the bug where adding a name to the autocomplete list but forgetting to handle it in the parser causes the command to silently fall through to `kind: 'send'` (the literal `/foo` text would be sent as a message).
