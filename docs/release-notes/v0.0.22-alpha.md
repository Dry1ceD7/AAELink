# v0.0.22-alpha — Custom sidebar sections, Cmd+1..9 workspaces, Canvas persistence

**Released:** 2026-05-14

This release closes three more parity items from
`docs/parity-ui-audit-2026-05-11.md` (§1.1, §1.3, §14.1) and finishes the
Slack-class behaviour for the workspace rail and Canvas.

## What changed

### Frontend

- **§1.1 — Workspace switcher rail with `Cmd+1..9` shortcuts.**
  - `Cmd+1` to `Cmd+9` now switch between workspaces in the order they
    appear in the rail. Single-workspace users keep the legacy "jump to
    Nth channel" behaviour.
  - The rail itself is now hidden when the user only belongs to one
    workspace (Slack-parity — saves screen real estate).
  - Tooltips on each rail icon now show the workspace name **and** the
    keyboard shortcut, e.g. `Engineering  ⌘1`.

- **§1.3 — Custom sidebar sections.** Right-click any channel and use
  "Move to section" → pick an existing section or "Create new section…".
  Custom sections render between Starred and Channels with the same
  collapsible UI as the built-ins, and "Remove from section" demotes a
  channel back to the default Channels group. New helper
  `lib/sidebarSections.ts` (10 unit tests) handles slug-keying, reserved
  category protection, and channel grouping. Persistence rides on the
  existing `/api/channel-categories` endpoint.

- **§14.1 — Canvas persistence.** `CanvasEditor` now loads the channel's
  canvas on mount and auto-saves every 800 ms after edits. First save
  creates the canvas via `POST /api/docs/canvas`; subsequent saves issue
  a `PUT`. The toolbar shows a real "Saving…" spinner during writes and
  switches to "Saved at HH:MM" on success.

### Backend

- **`/api/docs/canvas?id=…`** — new single-canvas lookup that returns
  the full `content_blocks` JSON. The list endpoint omits blocks for
  payload-size reasons; this dedicated lookup is what the editor calls
  on mount. Access check covers creator, channel canvas, template, and
  explicit `shared_with` membership.

- **§3.5 — Channel intro CTAs.** The empty-channel welcome screen now
  surfaces three Slack-class call-to-action cards (Add description /
  Add members / Set channel topic) that wire to existing modals.
  Wrapped in a `<section aria-label="Channel introduction">` so screen
  readers land on it cleanly.

- **§3.7 — System messages now render in the main timeline.** The
  `SystemMessage` component existed and was wired into `MessageTimeline`
  but `app/home/page.tsx` had its own inlined post-list copy that didn't
  use it. Now `isSystemPost(post)` is checked in the page-level list so
  joined / left / topic-changed / pinned / archived events render in
  their muted gray "system" style instead of as user messages.

- **§4.2 — Menu keyboard nav.** New `lib/useMenuNav.ts` hook wires
  Up/Down/Home/End/Esc into any `role="menu"` portal, and the message
  more-menu in `ChatMessage.tsx` now uses it. First menuitem auto-focuses
  on open.

- **§2.4 — Channel info panel tabs.** Migrated from plain `<button>` rows
  to the project's `TabList` primitive so About / Members / Pinned now
  emit a full `role="tablist"` / `role="tab"` / `aria-selected` / `aria-controls`
  pattern, and each tab body is wrapped in `role="tabpanel"` with
  `aria-labelledby`. Arrow keys now navigate the tabs.

- **§1.5 — Channel row mute icon + mention vs unread differentiation.**
  Muted channels now show a `BellOff` icon and dim the channel name.
  Channels with `mention_count > 0` get a red pill (`12 new mentions`)
  instead of the standard blue unread badge. Source data comes from
  `/api/channels/unread`, which the page now fetches alongside the main
  `/api/channels` list and merges into the channel objects.

- **§1.5 — Channel context menu — Mark as read.** Right-click any channel
  and pick "Mark as read" to bump the channel's read cursor to now via
  `POST /api/collab/read-state` (mode=set). Closes the last
  outstanding action item from audit §1.5.

- **`/api/test`** now reads the version from `package.json` so the
  connectivity probe always reports the live release tag instead of
  the stale `v0.0.8-alpha` string.

### Cleanup & coverage

- New unit suite `tests/sidebarSections.test.ts` (10 tests) covering
  `sectionKey`, `sectionLabel`, `RESERVED_CATEGORIES`, and
  `groupChannelsBySection`.
- `ChannelContextMenu` learned to render a one-level submenu so "Move
  to section" can fan out to existing custom sections + "Create new
  section…" without exploding the top-level menu.
