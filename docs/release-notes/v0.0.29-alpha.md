# v0.0.29-alpha — User Profile Pane (RHS), test harness, vitest 4 docblock env

**Released:** 2026-05-15

Closes audit §9.2. Replaces the popup `UserProfileCard` with a right-rail
`<UserProfilePanel>` that's deep-linkable, accessible, and slots into the
same rail real-estate as `ChannelInfoPanel`, `ThreadPanel`,
`PinnedMessagesPanel`, and `MemberListPanel`.

## What changed

### Profile pane

New `app/components/UserProfilePanel.tsx`. Eight sections rendered top to
bottom:

1. Header with close X
2. Identity: avatar (click → existing `AvatarLightbox`), name, pronouns, title, `@username`
3. Status row: presence dot + label, custom status, local time
4. Action buttons: Message, Huddle, View full profile (disabled — reserves slot for a future full-page route)
5. Contact: email + copy, phone + copy
6. About me (free-text bio with empty-state fallback)
7. Role: title and department
8. Member since (joined date)

The pane is deep-linkable via `?profile=<userId>`. State and URL stay in
sync via two effects in `app/home/page.tsx`. Pressing Esc, the X button,
or clicking outside the chat pane closes it.

### Right-rail mutual exclusion

Only one of `channelInfo` / `thread` / `pinnedPanel` / `memberList` /
`profile` is shown at a time. New `closeAllRailPanes()` helper clears
every rail-pane state at once. New `openProfilePane(uid)` helper closes
all panes then sets `profilePaneId`. Mention clicks, avatar clicks, and
hovercard "View full profile" all route through `openProfilePane` for
consistent behavior.

### Test harness — DOM tests now possible

Added `@testing-library/react`, `@testing-library/dom`, and `happy-dom`
as dev dependencies. `vitest.config.ts` keeps the `node` default
environment (existing 1,357 `*.test.ts` tests rely on it) and switches
component tests under `tests/**/*.test.tsx` to `happy-dom` via the
Vitest 4 docblock pattern (`@vitest-environment happy-dom`).

`tests/userProfilePanel.test.tsx` — 10 tests covering:

| # | Test |
|---|------|
| 1 | Renders nothing when `userId` is null |
| 2 | Loading state visible during fetch |
| 3 | Renders the name once fetched |
| 4 | Esc key closes the pane |
| 5 | X button closes the pane |
| 6 | Message button calls `onMessage` with userId |
| 7 | Huddle button calls `onHuddle` with userId |
| 8 | "View full profile" disabled without callback |
| 9 | Error state with Retry on fetch failure |
| 10 | Department renders from API response |

### Removed

- `app/components/UserProfileCard.tsx` — popup variant retired

### `AvatarLightbox` doc-comment refresh

Reference to `UserProfileCard` updated to `UserProfilePanel` so future
readers track the new home.

## Process notes

The Superpowers TDD discipline caught one config drift: Vitest 4.1.5
removed `environmentMatchGlobs`, so my initial `vitest.config.ts` patch
that wired component tests to `happy-dom` was a no-op. Tests failed
with `document is not defined`. Switched to the docblock
`@vitest-environment happy-dom` per the Vitest 4 release notes.
RED-GREEN caught the misconfiguration before any production code shipped.

The brainstorming → writing-plans → executing-plans flow paid off:

- The plan estimated 10 tests; the harness install added 30 minutes (not in the plan)
- The vitest config drift (~5 min) was discovered before any production code
- Total elapsed time matched the plan's ~2.5h estimate
