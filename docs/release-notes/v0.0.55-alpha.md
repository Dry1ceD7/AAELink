# v0.0.55-alpha — `<SearchFiltersChips>` primitive + helper extension (TDD)

**Released:** 2026-05-19

Adds a reusable visual chip strip for parsed search filters. Built on the v0.0.53 `parseSearchFilters` foundation. Two new pure helpers (`removeFilterToken`, `formatFilterChip`) extend `lib/searchFilters.ts`. Like v0.0.53, this release was written test-first.

## What changed

### `lib/searchFilters.ts` — two new helpers + `FilterKey` type

```ts
export type FilterKey = 'from' | 'in' | 'before' | 'after' | 'has'
export function removeFilterToken(raw: string, key: FilterKey): string
export function formatFilterChip(key: FilterKey, value: string): string
```

Behavior pinned by 13 new tests in `tests/searchFiltersChip.test.ts`:

`removeFilterToken`:

- Strips a single `<key>:<value>` token (case-insensitive on the key) and trims/collapses whitespace.
- Only removes the *first* occurrence — a query like `from:alice deploy from:bob` returns `deploy from:bob`. This is the right behavior for chip removal: clicking one chip removes one value, not all.
- Returns the original string unchanged when the key isn't present.
- Handles a query that is *only* the filter token (returns empty string).

`formatFilterChip`:

- Identifier filters (`from`, `in`, `has`) format as `from: alice` / `has: link` (colon + space, mirroring the original token shape).
- Date filters (`before`, `after`) format as `before 2025-01-01` (single space, no colon — reads cleaner when the value is itself date-shaped).

### New primitive: `<SearchFiltersChips>` (`app/components/primitives/SearchFilters.tsx`)

```ts
export interface SearchFiltersChipsProps {
  filters: SearchFilters     // from `parseSearchFilters(query)`
  query: string              // the raw query string
  onRemove: (newQuery: string) => void
  className?: string
}
```

Renders one removable pill per active filter. Click the X to remove a filter — the component delegates the string surgery to `removeFilterToken` and emits the new query via `onRemove(newQuery)`. Returns `null` when no filters are active so callers can place it unconditionally.

Markup is `role="list"` with `role="listitem"` chips and per-chip `aria-label="Remove filter ..."` on the X buttons. Keyboard users can Tab into a chip and press Enter/Space to remove it.

### CSS additions (`app/styles.css`)

New `Design System Tokens (v0.0.55 SearchFiltersChips primitive)` block at the bottom defines `.ds-search-filters` (the strip), `.ds-search-filter-chip` (the pill — uses the existing `--mm-mention-bg` / `--mm-mention-text` tokens for visual consistency with @mention rendering), `.ds-search-filter-chip-label`, and `.ds-search-filter-chip-remove` (the X button with hover background + focus-visible ring + reduced-motion guard).

### What's intentionally NOT done

The existing `GlobalSearchModal.tsx` chip UI (the `search-filter-pill*` block in `app/styles.css`) is preserved as-is, because it renders per-chip *icons* (User, Hash, Paperclip, Pin, etc.) that the new primitive doesn't carry. The primitive is staged for adoption in any *future* search surface (e.g., a sidebar or in-channel search input) where the simpler, icon-less chip is appropriate.

This keeps v0.0.55 reviewable in <5 min and avoids regressing the existing visual.
