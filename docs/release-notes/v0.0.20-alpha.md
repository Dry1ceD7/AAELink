# AAELink v0.0.20-alpha — Puzzle Box Block-Tree Documents

**Released:** 2026-05-14
**Focus:** Rebuild the Documents module so a template is a tree of typed,
swappable blocks — logo, sender header, recipient, delivery, order meta,
line items, totals, terms, signature. Pick a different client and every
block bound to that client (logo, name, address, contact, legal text)
swaps in one move. Drag to rearrange. Override any field per-document
without touching the template.

This release deletes two legacy code paths (the docx-with-placeholders
templates panel and the one-shot assemble endpoint) and consolidates the
Documents API around the block-tree model.

---

## 🧩 Block-tree model

Every template now lives at `aaelink.document_templates.block_tree` (JSONB,
`schema_version='2'`). The shape is:

```ts
type DocumentTree = {
  schema_version: '2'
  page_size: 'A4' | 'Letter' | 'Legal' | 'A3' | 'A5'
  blocks: Record<BlockId, Block>
  pages: Page[]
  style_tokens?: Record<string, string>     // CSS vars for branding
  locale_overrides?: …                      // reserved for v0.0.21
}
```

Each `Block` has a `type` (one of 14), absolute `layout` (mm), optional
`style`, and a `lock` flag for blocks the per-document UX must not delete.

### Typed block library

| Type | Default purpose |
|------|-----------------|
| `logo` | Client / workspace logo. Default binding: `client.logo_bucket_key` |
| `sender_header` | Your company info — `workspace.name/address/tax_id/contact` |
| `recipient` | Bill-to. Default binding: `client.*` |
| `delivery_address` | Ship-to. Independent of recipient |
| `order_meta` | Document number, date, customer no, PO no, page label |
| `line_items` | Table — columns are individually bindable |
| `totals` | Subtotal / tax / total — values are slots, often formulas |
| `terms` | Title + body — defaults to `client.legal_boilerplate` |
| `signature` | Image + printed name + title + date |
| `note` | One-line free text (e.g. "Thank you for your order.") |
| `text` | Free paragraph |
| `image` | Static or dynamic image |
| `divider` | Horizontal rule |
| `spacer` | Vertical gap |

Every block declares default `recognizer_hints` (aspect ratio, keywords,
typical page anchor) so a future OCR-driven recognizer can propose block
boundaries from a sample image.

### Slot model — the swap mechanic

Every block input is a `Slot`:

```ts
{ source: 'manual' | 'client' | 'workspace' | 'assembly' | 'ticket' | 'user' | 'formula',
  path: string,
  fallback: string }
```

- `client.logo_bucket_key` — the logo that swaps when you pick a different client.
- `workspace.name` — your company name; stays put.
- `assembly.line_items[0].qty` — pulls from the in-flight `PuzzlePiece`.
- `formula:sum:assembly.line_items[].amount` — computed at render: `sum`, `avg`, `min`, `max`, `count`.

The resolver is in `lib/puzzleBox/resolve.ts`. The serializer (`lib/puzzleBox/serialize.ts`) walks the tree, emits HTML with mm-positioned blocks, and Stirling-PDF renders the final PDF.

### Per-document overrides

When a user generates a single document they can override any slot for
*that one output* without touching the template. Stored as
`aaelink.document_assemblies.overrides`, keyed by `<block_id>.<input_path>`.
This is the structured version of the "60 day, manual override" hand-edit
on a printed Order Confirmation.

## 🎨 PuzzleBoxEditor

`app/components/PuzzleBoxEditor.tsx` is the new drag-resize-rearrange editor:

- Three columns: palette · canvas (mm-accurate page) · inspector.
- Drag any block to move, grab the bottom-right handle to resize.
- Keyboard a11y: arrow keys nudge by 1mm, Shift+arrow by 5mm, Cmd/Ctrl+Backspace deletes.
- Highlight blocks bound to `client.*` in green so the swap targets are obvious.
- Top-bar **Preview client** dropdown — pick a customer and the full preview re-renders.
- Live preview iframe debounces refresh on every change.
- Lock per-block to prevent end-users from removing it during per-document overrides.

### Inspector — bindings

Every input shows up as a row with a source picker (`manual`/`client`/`workspace`/`assembly`/`ticket`/`user`/`formula`). The inline hint reminds the user what each source means: *"Swaps when the bound client changes."*

## 🌱 Seed catalogue

`lib/puzzleBox/seedTemplates.ts` ships with a fully-wired **Order Confirmation** template that mirrors the AAE reference document from the project photo: logo top-left, sender header centre, recipient + delivery stacked, order meta top-right, line items, totals, terms, signature, thank-you note. One click to insert from `HtmlTemplatesPanel`'s empty state.

`POST /api/documents/templates/seed` is the admin endpoint backing it.

## 🔌 New / extended API endpoints

| Method | Path | Purpose |
|--------|------|---------|
| GET    | `/api/documents/templates?with_tree=1` | Returns the full block tree |
| POST   | `/api/documents/templates`              | Now accepts `block_tree` + `style_tokens` |
| PATCH  | `/api/documents/templates`              | Now accepts `block_tree` + `style_tokens` + `required_fields` |
| POST   | `/api/documents/templates/preview`      | Resolve a tree against a sample piece, returns HTML |
| GET    | `/api/documents/templates/seed`         | Seed catalogue listing |

## Known limits / follow-ups

- The block recognizer (`recognizer_hints` on every block spec) is reserved
  but not yet hooked to Stirling-PDF OCR coordinates. Manually building a
  template is fast enough that this is P2.
- Workspace branding admin UI (the source for `workspace.*` slots) is not
  yet shipped — the assemble stage falls back to AAE defaults at render.
- Editor saves always create a new template version. A "save-in-place"
  toggle is planned for v0.0.21.
- Per-locale string overrides exist in the schema (`locale_overrides`)
  but the editor does not surface them yet.
