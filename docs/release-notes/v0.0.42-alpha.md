## What changed

### `scripts/gen-openapi.mjs` (new)

Walks every `route.ts` under `app/api/`, picks up the `tracedRoute('METHOD', '/api/path', _IMPL)` lines, and emits `docs/openapi.json` (OpenAPI 3.1). Each operation carries:

- `summary` — `<METHOD> <path>` for quick grepping
- `tags` — first directory under `/api/` (e.g. `admin`, `messages`, `webhooks`)
- `description` — picks up the `// keep: <reason>` markers added in v0.0.30 so the generated spec carries category intent (slack-compat / enterprise admin / external integration / etc.)
- `parameters` — auto-extracted `{param}` segments from the OpenAPI path
- `responses` — boilerplate 200/401/403/404 stubs

**Output for v0.0.42:**

```
$ npm run openapi
OpenAPI spec written to docs/openapi.json
  routes scanned: 237
  operations:     448
  tags:           71
```

The spec is method/path surface only — request/response JSON-Schema bodies are not introspected because route handlers don't carry typed Zod schemas yet. Adding those is a separate effort tracked in the roadmap; for now this gives a hand-out-to-clients route inventory in 30 seconds.

`npm run openapi` added to `package.json`.

### `e2e/chat/reactions.spec.ts` (new)

Two Playwright specs:

- Hover toolbar exposes a reaction button after a message is sent
- Clicking a quick reaction renders a count chip (`'1'`) next to the message

Uses the existing `authedPage` fixture and matches the pattern of `e2e/chat/messaging.spec.ts`. Selectors fall back through aria-label, title, and class-name so a UI label rename doesn't immediately break the spec.

### `app/components/WorkflowBuilder.tsx` — inline-style cleanup round 1

Replaced 14 inline `style={{...}}` blocks (mostly layout shells) with five new utility classes in `app/styles.css`:

| Class | Replaces |
|-------|----------|
| `.workflow-shell` | Outer flex column, `var(--mm-main-bg)`, `var(--mm-text)` (used in both list and edit views) |
| `.workflow-toolbar` / `.workflow-toolbar--edit` | Top toolbar row, padding + bottom-border |
| `.workflow-toolbar-left` | Left-aligned `display: flex; align-items: center; gap: 10px` cluster |
| `.workflow-section-label` | Uppercase label above each builder section |
| `.workflow-canvas` / `.workflow-canvas-row` | Scrolling vertical-center canvas + 480-px-max content rail |
| `.workflow-rail` / `.workflow-rail--short` / `.workflow-rail-center` | Vertical 2-px-wide rail bars + their centering wrappers |

Result: **71 → 57 inline blocks (−14)** in `WorkflowBuilder.tsx`. Themes can override via the new classes; reduced-motion preferences continue to work because no animation moved into the inline styles.

## Out of scope (deferred)

- **Re-running the generator on every build.** The spec is regenerated explicitly with `npm run openapi`; wiring it into the build hook is one line in `package.json`'s `scripts.build` chain but adds non-determinism if the working tree has uncommitted route edits. Tracked separately.
- **Spec-driven SDK generation.** `openapi-typescript` and friends can consume `docs/openapi.json` to emit typed clients. Adding the generator is one PR; not blocking anyone today.
