# AAELink v0.0.18-alpha — Slack UI/UX Parity, A11y, Ticketing v2 & Document Automation

**Released:** 2026-05-14
**Focus:** Close the visual/interaction/a11y gap with Slack's web client, ship Jira-grade guarded ticket workflows with business-hours-aware SLA, and land the Puzzle Box document automation pipeline.

## ♿ Accessibility Foundation (Audit P0s)

A new shared a11y primitives library at `app/components/a11y/` standardizes how we build tab strips, toggles, icon buttons, confirms and announcements.

| Primitive | File | Purpose |
|-----------|------|---------|
| `TabList` / `TabPanel` | `TabList.tsx` | WAI-ARIA `role=tablist/tab/tabpanel` with arrow-key nav, horizontal & vertical orientation |
| `tabListKeyAction` | `tabListKeyHandler.ts` | Pure key→nextIndex reducer (covered by `tests/tabListKeyHandler.test.ts`) |
| `ToggleButton` | `ToggleButton.tsx` | `role=switch` + `aria-checked` for binary settings |
| `IconButton` | `IconButton.tsx` | Always-labelled icon button (no silent buttons) |
| `useAriaLive` | `useAriaLive.tsx` | Polite/assertive live-region announcer for SR users |
| `useConfirm` | `useConfirm.tsx` | Promise-based replacement for `window.confirm()` backed by `ConfirmDialog` |

### `window.confirm()` elimination
All 15 `confirm()` callsites have been migrated to `ConfirmDialog`/`useConfirm`. Native unstyled modals no longer interrupt destructive flows.

### Tab strips migrated to `TabList`
- `PreferencesModal` (vertical, 7 tabs)
- `IntegrationsPanel`, `MarketplacePanel` (horizontal)
- existing tab-strip surfaces audited and brought onto the same primitive

### Reduced motion
A global `@media (prefers-reduced-motion: reduce)` catch-all in `app/styles.css` neutralizes every non-essential transition, animation and shimmer.

### Reactions (§3.6)
Reaction chips now expose `aria-pressed` and a descriptive `aria-label` (`":heart: — 3 reactions, you reacted"`). A new `+` button opens the picker directly from the reaction row.

### Message keyboard navigation (§3.1)
`useMessageKeyNav` adds Slack-style hotkeys to the timeline (only when no input is focused):

| Key | Action |
|-----|--------|
| `J` / `↓` | Next message |
| `K` / `↑` | Previous message |
| `T` | Open thread on focused message |
| `R` | Open reaction picker |
| `E` | Edit (own messages only) |
| `Esc` | Clear keyboard focus |

The currently focused message gets a `.message--kb-focused` ring and is auto-scrolled into view.

### Hover toolbar reachable by keyboard (§4.1)
`ChatMessage` is now a focusable `role=article`; tabbing or arrow-keying onto a message reveals the actions toolbar — a previously mouse-only surface.

### Mention warnings (§5.3)
Composer continues to warn when `@channel` / `@here` / `@all` would notify many users; the warning now adheres to ARIA-correct alert patterns.

## 🎫 Ticket State Machine + SLA v2 (Backend)

### Jira-grade guarded transitions
`lib/ticketStateMachine.ts` evaluates every status change through typed guards before the database is touched.

| Guard | Trigger |
|-------|---------|
| `forbidden_role` | Actor is not assignee, creator, IT, or admin |
| `assignee_required` | Move to `pending` / `in_progress` without an assignee |
| `resolution_note_required` | `in_progress → resolved` with note shorter than 10 chars |
| `resolution_category_required` | Resolve without one of `fixed`/`workaround`/`duplicate`/`wont_fix`/`cannot_reproduce`/`user_error`/`completed` |
| `four_eyes_violation` | Resolver tries to also close — only a different user may close (admin override) |
| `reopen_reason_required` | `closed → open` or `resolved → in_progress` without ≥5 char reason |
| `force_close_requires_reason` | Admin force close without reason |

`POST /api/tickets/[id]/transition` is the single guarded endpoint. Returns HTTP 409 with `{ error, hint, from, to }` on guard rejection. Every transition is logged to a new `ticket_transitions` table and mirrored into the existing activity log. The legacy `PATCH /api/tickets/[id]` continues to handle non-status updates; the UI now dispatches status changes through the new endpoint.

### `TicketsPanel` & `TicketDetailModal` rewiring
- Status drop-downs now include the new `pending` state.
- Priority dropdowns replaced the legacy `urgent` value with `high` to match `slaEngine.isTicketPriority`.
- A new `transitionTicket` helper handles HTTP 409 by opening a styled, focus-trapped `TransitionDialog` that collects the missing metadata (resolution note + category, reopen reason, force-close reason) and re-submits — no more native `window.prompt()` in the ticket flow.
- Kanban drag-and-drop, keyboard-pickup-and-drop and the detail modal all flow through the same guarded endpoint.

### `TransitionDialog`
A new modal component (`app/components/TransitionDialog.tsx`) renders three modes (`resolve`, `reopen`, `force_close`) with field-level validation, ARIA labelling, focus trap and Esc-to-close. Mounts as a portal and is reused by both `TicketsPanel` and `TicketDetailModal`.

### SLA v2 — business hours, dual clocks, pausable
`lib/slaEngine.ts` now exposes:

- `addBusinessMs(startMs, budgetMs, businessHours)` — pure forward walk through open windows, skipping holidays
- `calculateSlaDueV2(start, policy, businessHours)` — dual `first_response_due_at` + `resolution_due_at`
- `effectiveDue(originalDueAt, pausedTotalMs, pausedAt, now)` — accounts for paused time
- `defaultPolicy(workspaceId, priority)` — sensible fallback when no policy row exists

New columns on `aaelink.tickets`: `resolution_note`, `resolution_category`, `resolved_by`, `resolved_at`, `first_response_at`, `first_response_due_at`, `sla_paused_at`, `sla_paused_total_ms`, `sla_policy_id`, `force_closed`, `kanban_order`.

New tables:
- `aaelink.business_hours` — workspace-scoped schedule + holidays + IANA timezone
- `aaelink.sla_policies` — per-priority response/resolution targets, pause states, BH link
- `aaelink.ticket_transitions` — every guarded transition with metadata

### Admin endpoints
- `GET/POST /api/business-hours` — workspace business-hours schedules
- `GET/POST /api/sla/policies` — per-priority SLA policies (admin-only POST)

### Admin UI
A new **Ticketing Settings** panel (`app/components/admin/TicketingSettingsPanel.tsx`) is mounted on `/admin`. It lets platform admins:

- Pick a workspace from a dropdown
- Configure first-response and resolution targets per priority (with default values seeded from `slaEngine.getSlaTarget`)
- Pick which statuses pause the SLA clock per priority
- Bind a policy to a business-hours schedule
- Create a business-hours schedule with per-day open windows (HH:MM pickers) and a holidays list (YYYY-MM-DD)

### Tests
- `tests/ticketStateMachine.test.ts` — 29 tests covering every guard + planned effects
- `tests/slaEngineBH.test.ts` — business-hours walker, weekend/holiday rollover, pause math

## 📄 Puzzle Box — Document Automation (Backend)

A typed pipeline that turns raw text or pre-built data into a branded PDF and posts it to a channel. Lives at `lib/puzzleBox/`.

### Stages
1. **Ingest** (`ingest.ts`) — accepts `raw_text` or a pre-built `PuzzlePiece`
2. **Extract** (`extract/router.ts`) — auto-routes to `regex`, `llm`, or both; LLM falls back to regex when `AI_GATEWAY_URL` is absent
3. **Normalize** (`normalize.ts`) — coerces dates, numbers and currency; resolves customer linkage by `client_profile.code` or email
4. **Assemble** (`assemble.ts`) — merges the `PuzzlePiece` with a versioned `document_template` and a branded `client_profile`
5. **Render** (`render.ts`) — Stirling-PDF: HTML → PDF, compress, optional logo stamp, staging watermark
6. **Deliver** (`deliver.ts`) — writes to S3 + posts a message with the file attachment

### Boundary type — `PuzzlePiece`
The single versioned (`schema_version: '1'`) data shape between extraction and assembly. Extraction strategies plug in independently; downstream stages remain stable.

### Endpoints
| Route | Purpose |
|-------|---------|
| `GET/POST /api/documents/templates` | List active templates / create a new versioned template (admin) |
| `GET/POST /api/documents/assemblies` | List recent assemblies / create a new one |
| `GET /api/documents/assemblies/[id]` | Full assembly + per-stage pipeline log |
| `POST /api/documents/assemblies/[id]/ingest` | Drive the pipeline forward from raw text |
| `POST /api/documents/assemblies/[id]/run` | Resume the pipeline from its current stage |

### New schema
- `aaelink.client_profiles` — branded customer (logo, address, tax ID, legal boilerplate)
- `aaelink.document_templates` — versioned HTML/CSS templates with required-field metadata
- `aaelink.document_assemblies` — pipeline state, rendered HTML, S3 key, delivery target
- `aaelink.document_pipeline_log` — every stage transition with duration + detail

### Tests
- `tests/puzzleBox.test.ts` — regex extractor, router strategy, normalize coercion + customer linkage

## Known Issues / Follow-ups

- LLM extraction in Puzzle Box requires `AI_GATEWAY_URL`; without it the router silently falls back to regex (with a `llm_unavailable_fallback_regex` warning).
- Stirling-PDF must be reachable for the render stage; a probe at `lib/stirlingPdf.isStirlingAvailable()` short-circuits with `stirling_unavailable` otherwise.
- Admin UIs for document templates and client profiles are not yet shipped — the endpoints are ready but the panels arrive in v0.0.19-alpha. (SLA policies + business hours admin **landed** in this release — see the Ticketing Settings panel under `/admin`.)
- v0.0.19-alpha will pick up the remaining v0.0.18 P1/P2 items (Slack visual parity batch 2: workspace switcher rail, sidebar sections, hovercard, huddle WebRTC wiring, etc.).
