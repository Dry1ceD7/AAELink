# AAELink v0.0.8-alpha

Release notes for tag `v0.0.8-alpha`.

## Highlights

This release achieves **full Slack API method-level parity** — every one of Slack's **30 API method groups** now has a corresponding AAELink implementation. The focus was production hardening and closing the remaining Slack-class gaps across conversations, chat, users, views/modals, OAuth, workflows, functions, lists, reactions, usergroups, and more.

- **25 new API routes** across 20 Slack method groups.
- **Batch 34 DDL migrations** adding 14 new database tables + 7 additive columns.
- **4 new worker job handlers** for workflow execution, function execution, scheduled message delivery, and OAuth token cleanup.
- **207 total API route files**, zero TypeScript errors.
- **30/30 Slack API method groups** now have full AAELink equivalents.

## What is new

### Conversations API (7 routes)

Full Slack `conversations.*` parity across 7 dedicated endpoints.

#### Conversations History
- **API**: `GET /api/conversations/history?channel_id=&limit=&oldest=&latest=&cursor=&inclusive=`
- Paginated message history with time-range filtering.
- Thread reply counts, reaction aggregations, edit tracking.
- Membership-gated access for private channels and DMs.

#### Conversations List
- **API**: `GET /api/conversations/list?types=&limit=&cursor=&exclude_archived=&team_id=`
- Type-filtered listing: `public_channel`, `private_channel`, `mpim`, `im`.
- Archive exclusion, workspace scoping, cursor pagination.
- Per-channel `is_member` indicator and member counts.

#### Conversations Replies
- **API**: `GET /api/conversations/replies?channel_id=&ts=&limit=&cursor=`
- Threaded reply retrieval with parent message inclusion.
- Reaction aggregation per reply.
- Time-range filtering and cursor pagination.

#### Conversations Mark
- **API**: `POST /api/conversations/mark`
- Mark a conversation as read up to a given timestamp.
- Upsert into `read_state` table with compound (user_id, channel_id) key.

#### Conversations Open / Close
- **API**: `POST /api/conversations/open`
- Open or resume DM/group DM conversations between users.
- Deduplicates existing conversations — idempotent.
- Supports both 1:1 DMs and multi-party group DMs (MPIMs).

#### Conversations Info
- **API**: `GET /api/conversations/info?channel_id=`
- Full channel metadata: topic, purpose, member count, pin count, message count.
- Role verification for the requesting user.
- *(Shipped in prior batch, documented here for completeness)*

#### Conversations Members
- **API**: `GET/POST/DELETE /api/conversations/members`
- Bulk invite/kick with system message logging.
- Default-channel protection (cannot kick from #general).
- *(Shipped in prior batch, documented here for completeness)*

### Chat API
- **API**: `POST /api/chat`
- Unified bot/app messaging surface covering all **8 Slack `chat.*` methods** via `action` parameter:
  - `postMessage` — send a message with Block Kit blocks.
  - `postEphemeral` — send visible-to-one-user messages.
  - `update` — edit a message by timestamp.
  - `delete` — delete with ownership/admin checks.
  - `unfurl` — provide URL unfurl metadata.
  - `meMessage` — post `/me` style messages.
  - `getPermalink` — generate stable deep-link URLs.
  - `scheduleMessage` — schedule future message delivery.

---

### Views / Modals API
- **API**: `POST /api/views`
- Block Kit modal/dialog management covering Slack `views.*`:
  - `open` — open a new modal with trigger_id.
  - `push` — push a view onto the modal stack.
  - `update` — update an existing view by view_id.
  - `publish` — publish a Home tab view for a user.
- Hash-based optimistic locking for concurrent updates.

### Dialog API (Legacy)

## Known issues

- Workflow execution currently runs sequentially in the worker; consider parallel step execution for branching workflows at scale.
- OAuth token exchange does not validate redirect_uri against registered app URIs — implement in production.
- AI assistant `search_context` uses `ILIKE` for message search — consider tsvector for production workloads.
- Views/modals are stateless (not persisted in DB) — for multi-server deployments, consider Redis-backed view state.
- List items use `JSONB` values without schema validation at the DB level — validation is application-side only.
