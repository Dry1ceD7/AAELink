# AAELink v0.0.19-alpha — Documents Module v2

**Released:** 2026-05-14
**Focus:** Unify the two parallel document subsystems (legacy "Documents" and "Puzzle Box"), expose the assembly pipeline through a real UI, replace the dual-schema mess with one canonical schema, and wire ticket → document round-trip.

---

## 🔧 Schema consolidation (P0)

Before this release the migrate file declared `aaelink.client_profiles` and `aaelink.document_templates` **twice**. Postgres only ran the first `CREATE TABLE IF NOT EXISTS`, so the Puzzle Box columns added in v0.0.18 silently weren't applied on existing v1 deployments.

`lib/migrate.ts` now:

- Keeps the original `CREATE TABLE` for both tables (~line 1842)
- Adds Puzzle Box columns (`logo_bucket_key`, `brand`, `address`, `kind`, `version`, `html_source`, `css_source`, `required_fields`, `page_size`) via idempotent `ALTER TABLE … ADD COLUMN IF NOT EXISTS`
- Backfills the new `address` JSONB blob from the legacy flat columns when it's empty
- Creates the unique indices (`uq_client_profiles_ws_code`, `uq_doc_templates_ws_kind_ver`) — the client-profile constraint is now `WHERE code <> ''` so legacy rows with empty codes don't conflict
- Adds a `ticket_id` column to `document_assemblies` for the new ticket → assembly link

`/api/clients` POST/PATCH writes both the legacy flat address columns **and** the canonical `address` JSONB blob, so the Puzzle Box `assemble.ts → loadClient` reads the same shape regardless of when the row was created. `/api/clients` also gained the missing `DELETE` handler the existing `ClientsPanel` was already calling.

The duplicate `CREATE TABLE` blocks have been removed, and the migration is verified idempotent on both fresh DBs and v1 deployments.

## ✨ Assembly Pipeline UI (P0)

A new tab in the Documents module surfaces every Puzzle Box assembly:

`app/components/AssemblyPipelinePanel.tsx`

- Filter chips: All / Ingested / Extracted / Normalized / Assembled / Rendered / Delivered / Failed (each with live counts)
- One row per assembly with stage dots showing past / current / failed states
- Expand a row → per-stage log table (stage, status, duration, detail JSON)
- Action buttons:
  - **Resume from last good stage** (or **Run next stage** when partial)
  - **Download PDF** (when render or later)
  - **Discard** (deletes the assembly + log + S3 object)
  - **View ticket** (when the assembly was created from a ticket)

### `AssemblyIngestModal`

`app/components/AssemblyIngestModal.tsx`

The "New assembly" modal supports three input modes:

| Mode | Behaviour |
|------|-----------|
| **Paste text** | Sends `raw_text` to the ingest endpoint; extraction strategy is configurable (auto / regex / llm) |
| **Upload file** | Reads UTF-8 text from the file and feeds it to ingest |
| **Pre-built JSON** | Skips extraction; the user supplies a `PuzzlePiece` directly |

The modal also picks template + client + delivery channel and threads `ticket_id` through when launched from a ticket.

### Backend additions
- `DELETE /api/documents/assemblies/[id]` — discards the row, the pipeline log (FK cascade), and the S3 PDF
- `GET /api/documents/assemblies/[id]/download` — streams the rendered PDF
- `PATCH /api/documents/templates` — admin endpoint to deactivate / rename a template (used by the deactivate flow in the HTML editor)
- `GET /api/documents/templates` — now optionally returns inactive rows with `?include_inactive=1`, and excludes legacy binary uploads (where `kind='binary'` and `html_source=''`)

## 🧩 HTML / CSS Template editor (P1)

`app/components/HtmlTemplatesPanel.tsx` is the new "HTML Templates" tab in the Documents module. It targets the Puzzle Box columns specifically, leaving the legacy `TemplatesPanel` (binary docx/pdf uploads) alone:

- Pick a kind (`invoice`, `quote`, `sow`, `report`, `memo`, `receipt`, `custom`)
- Edit HTML and CSS source side-by-side
- Pick a page size (A4, Letter, Legal, A3, A5)
- Declare required fields — the `assemble` stage fails fast if any are missing on the `PuzzlePiece`
- Save bumps the version automatically per `(workspace_id, kind)`
- Toggle a live preview that renders the template with a sample `PuzzlePiece` via `lib/templateEngine.resolveTemplate` — same engine the server uses
- Deactivate hides the template from the assembly picker without losing the version

## 🎫 Ticket → Document round-trip (P1)

The ticket detail modal grew a **Generate document** action (next to Copy Link / Refresh). Click it to open `AssemblyIngestModal` pre-filled with:

- `ticketId` set so the deliver stage links the assembly back
- `initialRawText` = `ticket.title + ticket.description` (so regex/LLM extraction has something to chew on)

When the deliver stage runs:

1. Posts the rendered PDF to the channel (if one is selected)
2. **New:** if `ticket_id` is set, adds a comment to the originating ticket with a markdown link to `/api/documents/assemblies/[id]/download` and the file size
3. Bumps `tickets.updated_at` so the ticket list re-sorts

The ticket comment is best-effort — failures don't stop the channel post or fail the deliver stage.

## 📚 Documents tab map

The Documents module now has six tabs:

| Tab | Subsystem | Purpose |
|-----|-----------|---------|
| **Files** | legacy | Upload + browse + OCR + download + preview |
| **Templates** | legacy | Binary docx/pdf templates with `{{placeholder}}` autodetection |
| **HTML Templates** | Puzzle Box | Versioned HTML/CSS templates with required-field declarations |
| **Clients** | shared | Client profiles (now writes both flat + JSONB address) |
| **Quick assembly** | legacy | Single-shot template→file substitution wizard |
| **Pipeline** | Puzzle Box | Full ingest → extract → normalize → assemble → render → deliver pipeline with per-stage observability |

Pick "Quick assembly" when you have all the data; pick "Pipeline" when you have raw text or want LLM extraction.

## Known Issues / Follow-ups

- The HTML template editor opens the existing template for editing but always saves as a new version. In v0.0.20 we'll add an explicit "Edit current version" mode for typo fixes.
- Pipeline UI does not yet support file ingestion via Stirling-PDF text extraction for binary inputs (PDFs / Word). Today the user must paste the text; v0.0.20 will route the upload path through Stirling automatically.
- `AssemblyIngestModal` reads files via `File.text()` (UTF-8). Binary files like PDFs will look like garbage to the regex extractor — use the Files tab to OCR/convert first.
- The Pipeline panel's "Resume from last good stage" relies on the orchestrator's behaviour of treating `stage='failed'` as a restart from `extracted`. This is correct, but in cases where extraction succeeded and only render failed, the user pays the LLM/regex cost again. v0.0.20 will track per-stage success on the assembly row and skip already-completed stages.
- v0.0.20-alpha picks up: alerting (Alertmanager), E2E tests, mTLS federation, audit log streaming, OpenAPI generation, and Slack visual parity batch 2 (workspace switcher rail, hovercard, etc.).
