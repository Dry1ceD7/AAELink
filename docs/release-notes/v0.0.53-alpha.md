# v0.0.53-alpha — Search filter parser extracted to `lib/searchFilters.ts` (TDD)

**Released:** 2026-05-19

Closes audit doc F11 (search filter operators) by extracting the previously-inline `parseFilters` function out of `GlobalSearchModal.tsx` into a dedicated, fully-tested library module. Built with Test-Driven Development — 18 tests written first (and watched fail), then the minimal implementation written, watched the suite go green.

## What changed

### New `lib/searchFilters.ts` (pure module, ~80 LOC)

Public surface:

```ts
export interface SearchFilters {
  text: string
  from?: string
  in?: string
  before?: string
  after?: string
  has?: string
}
export function parseSearchFilters(raw: string): SearchFilters
export function isValidDate(s: string): boolean
export function validateHasValue(s: string): boolean
```

The parser handles:

- `from:<username>` — author filter
- `in:<channel>` — channel filter
- `before:<YYYY-MM-DD>` and `after:<YYYY-MM-DD>` — date range
- `has:<link|file|attachment|pin|reaction>` — content type

Behavior pinned by tests:

- Plain queries pass through to `text` with whitespace collapsed.
- Filter keys are case-insensitive (`FROM:alice` → `{ from: 'alice' }`).
- Filter values are kept exactly as typed (case-sensitive) since the server side handles username/channel matching.
- Malformed `from:` (no value) leaves the colon in the text portion (matches Slack's parser behavior).
- Unknown prefixes (`foo:bar`) stay in text untouched.
- Three filters + free text decomposes correctly into all five fields.
- `isValidDate('2025-01-01')` → `true`; malformed → `false`.
- `validateHasValue('link' | 'file' | 'attachment' | 'pin' | 'reaction')` → `true`; otherwise → `false`. Case-sensitive (matches the API).

### `app/components/GlobalSearchModal.tsx` — refactor

- The previously-inline `parseFilters`, `FILTER_RE`, and the duplicated `SearchFilters` interface deleted (≈25 LOC removed from the component).
- Now imports from the new lib module: `import { parseSearchFilters, type SearchFilters } from '@/lib/searchFilters'`.
- Two callsites updated: `useMemo(() => parseSearchFilters(query), [query])` and the inner `doSearch` parser call.

### `FILTER_SUGGESTIONS` expanded

The autocomplete chips below the search box used to show a single generic `has:` suggestion. The audit asked for explicit per-type chips. Now there are four:

- `has:link` (Link2 icon, "Has a link")
- `has:file` (Paperclip icon, "Has a file or attachment")
- `has:pin` (Pin icon, "Pinned messages")
- `has:reaction` (Smile icon, "Has reactions")

### Tests

- New `tests/searchFilters.test.ts` — **18 tests** covering text-only, single-filter extraction (all five operators), multi-filter combinations, case-insensitive keys, malformed input, position-independence, and the two validators.
- TDD discipline: each block of tests was written, run, and watched fail with a `Cannot find package '@/lib/searchFilters'` error before the implementation file was created. Then the implementation was written, the suite re-run, and the green came up exactly once — no test churn during refactor.
