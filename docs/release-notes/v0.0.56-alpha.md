# v0.0.56-alpha — `<DataTable>` primitive + TicketingSettingsPanel adoption

**Released:** 2026-05-19

Closes the audit's last queued primitive gap (`<DataTable>`). Both tables in `TicketingSettingsPanel` are now driven by the design system instead of repeating per-row inline `padding: '8px 4px'` / `borderBottom: '1px solid rgba(0,0,0,0.05)'` styling on every cell.

## What changed

### New primitive: `<DataTable>` (`app/components/primitives/DataTable.tsx`)

```ts
export interface DataTableProps extends TableHTMLAttributes<HTMLTableElement> {
  fullWidth?: boolean   // adds `width: 100%` (default true)
  className?: string
  style?: CSSProperties
  children?: ReactNode
}
```

A thin wrapper that:

- Wraps its `<table>` in a `<div class="ds-table-scroll">` that handles horizontal overflow on narrow viewports — adopters drop the `<div style={{ overflowX: 'auto' }}>` wrapper they used to write per-table.
- Applies `.ds-table` + `.ds-table--full` classes that token-style nested `<thead>`, `<tr>`, `<th>`, `<td>` elements.
- Spreads any additional `<table>` HTML attrs through (so callers can still pass `aria-label`, `aria-describedby`, etc.).

The CSS-only approach was chosen over a more opinionated `columns: ColumnSpec[]` API because:

- Existing admin tables have heterogeneous cell content (inputs, buttons, selects, custom badges) that wouldn't compress well into a column-spec shape.
- The wrapping shape `<DataTable><thead>…</thead><tbody>…</tbody></DataTable>` keeps the diff trivially reviewable.

### CSS additions (`app/styles.css`)

A new `Design System Tokens (v0.0.56 DataTable primitive)` block at the bottom defines:

- `.ds-table-scroll` — `overflow-x: auto` wrapper
- `.ds-table` — `border-collapse: collapse`, `font-size: 13px`, color from `--mm-text`
- `.ds-table--full` — `width: 100%`
- `.ds-table thead tr` — `border-bottom: 1px solid rgba(0, 0, 0, 0.08)`, with a dark-mode override using `rgba(255, 255, 255, 0.08)`
- `.ds-table th` — `padding: 8px 4px`, `font-weight: 600`
- `.ds-table tbody tr` — `border-bottom: 1px solid rgba(0, 0, 0, 0.05)`, dark-mode override
- `.ds-table td` — `padding: 8px 4px`, `vertical-align: middle`

Dark-mode borders use `rgba(255, 255, 255, …)` so the divider lines are visible against the dark surface, matching the `[data-theme="dark"]` pattern already used elsewhere in `app/styles.css`.

### Adoption — `TicketingSettingsPanel.tsx`

Both tables migrated:

1. **SLA policies table** (Priority / First response / Resolution / Pause states / Business hours / Action) — outer `<div style={{ overflowX: 'auto', marginTop: 12 }}>` + `<table style={{ width: '100%', borderCollapse: 'collapse', fontSize: 13 }}>` collapsed to `<DataTable>`. Six `<th>` cells lost their `style={{ padding: '8px 4px' }}`.
2. **Business-hours table** (Name / Timezone / Schedule / Holidays) — same swap. Four `<th>` and per-row `<td>` cells lost their inline padding/border styling.

The `PolicyRow` sub-component also lost its per-cell `style={{ padding: '8px 4px' }}` on six cells. The cells that needed extra styling (`textTransform: 'capitalize'`, `whiteSpace: 'nowrap'`) keep only those specific properties — padding and border-bottom now come from the primitive.

### Inline-style block reductions

`TicketingSettingsPanel.tsx`: **~57 → ~37** inline `style={{ ... }}` blocks. The deletion is concentrated in the two table bodies and the `PolicyRow` component.
