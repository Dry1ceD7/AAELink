# External skills — auto-loaded catalogue

This workspace integrates four upstream skill collections under `.claude/skills/external/`. They live alongside the project's own `aaelink-*`, `bmad-*`, `superpowers-*`, and `caveman-*` skill catalogues and follow the same activation pattern: read the relevant `SKILL.md` (or use `discloseContext` when surfaced) when the trigger conditions match a task.

## Activation rules

1. **Always-on baseline** — The `karpathy-guidelines` skill (`.claude/skills/external/karpathy/karpathy-guidelines/SKILL.md`) and mattpocock's `tdd` skill (`.claude/skills/external/mattpocock/engineering/tdd/SKILL.md`) reinforce the project's existing TDD + simplicity discipline. Treat them as ambient context for any production-code change. They do not override AAELink's four gates or the Superpowers methodology — they layer on top.

2. **Task-triggered activation** — When a user request matches a skill's described trigger, read that `SKILL.md` before acting. Examples:
   - User says "debug" / "investigate failure" / "post-mortem" → `9arm/engineering/{debug-mantra,scrutinize,post-mortem}` and `mattpocock/engineering/diagnose`.
   - User wants TDD or red-green-refactor → `mattpocock/engineering/tdd` (read its bundled `tests.md`, `mocking.md`, `interface-design.md`, `deep-modules.md`, `refactoring.md` as needed).
   - User wants to break work into issues / tickets → `mattpocock/engineering/{to-issues,to-prd,triage}`.
   - User asks for review / sanity-check / second opinion → `9arm/engineering/scrutinize`.
   - User asks to compress for execs / PMs / VPs → `9arm/productivity/management-talk`.
   - User asks to scaffold a new skill → `mattpocock/productivity/write-a-skill`.
   - User wants a tracer-bullet prototype before committing to a design → `mattpocock/engineering/prototype`.
   - User mentions ECC-style agent harness, eval-first loops, agentic engineering, or LLM cost routing → `ecc/skills/{agentic-engineering,eval-harness,agent-harness-construction,cost-aware-llm-pipeline,context-budget,token-budget-advisor}`.
   - Stack-specific requests (Prisma, Postgres, Redis, NestJS, Vite, Nextjs Turbopack, Django, Spring, Quarkus, etc.) → `ecc/skills/<stack>-patterns` and matching `*-tdd` / `*-testing` / `*-security` siblings.

3. **Coexistence with project rules**
   - Caveman style still applies to chat prose. Skill content itself is normal markdown.
   - Superpowers four gates (`tsc --noEmit`, `eslint .`, `vitest run`, `next build`) still mandatory — external skills do not waive them.
   - AAELink hard rules (`getPool()`, `lib/migrate.ts`, audit, CSRF, realtime emit chokepoints) still authoritative.
   - Where an external skill conflicts with an AAELink-specific skill (e.g. `ecc/skills/database-migrations` vs project's `lib/migrate.ts` rule), the AAELink rule wins.
   - Where an external skill conflicts with another external skill, prefer the more specific / project-aligned one. Default tiebreaker: `mattpocock` > `9arm` > `karpathy` > `ecc` (mattpocock's TDD vocabulary already maps tightly onto the project's existing testing convention).

4. **License & attribution** — Each upstream's `LICENSE` / `README.md` / `CLAUDE.md` is preserved under the source's local root. When porting a skill verbatim into a new AAELink-specific skill, keep the upstream attribution line in the front matter or a `## Origin` section.

## Re-syncing

The four upstream repos were cloned into `_skills-import/` (gitignored as needed). To refresh:

```bash
cd _skills-import
for d in 9arm-skills mattpocock-skills andrej-karpathy-skills ecc; do
  (cd "$d" && git pull --ff-only) || true
done
cd ..
# then re-run the copy commands below and rebuild INDEX.md
bash .claude/skills/external/build-index.sh > .claude/skills/external/INDEX.md
```

Copy commands (initial integration):

```bash
cp -R _skills-import/9arm-skills/skills/{engineering,productivity,misc}      .claude/skills/external/9arm/
cp -R _skills-import/mattpocock-skills/skills/{engineering,productivity,misc} .claude/skills/external/mattpocock/
cp -R _skills-import/andrej-karpathy-skills/skills/karpathy-guidelines        .claude/skills/external/karpathy/
cp -R _skills-import/ecc/skills                                                .claude/skills/external/ecc/
```

`personal/`, `in-progress/`, and `deprecated/` buckets are intentionally excluded — they are upstream-private or unfinished.

## What this rule explicitly is not

- Not a re-implementation of the upstream skills. The local copies are the source of truth in this workspace.
- Not auto-execution. Skills still load on demand; this rule just makes the catalogue discoverable from every session.
- Not a replacement for the in-tree `aaelink-*` / `bmad-*` / `superpowers-*` skills. External skills augment, never override.
